# Telegram Serverless против двух VPS

Здесь код [@commongroundlabbot](https://t.me/commongroundlabbot), его Mini App и измерения для статьи. Цель эксперимента: запустить маленькое приложение без собственного сервера и сравнить его работу с двумя уже существующими VPS.

Это общий цифровой сад: полив даёт 120 единиц роста за две минуты. Поливать можно один раз за фиксированный минутный интервал. Время хранится в SQLite, рост рассчитывается при чтении. Первоначальный бот создан за одну итерацию с 6.1 Sol; затем выполнены функциональные проверки и расширенные замеры.

## Что измерено

SQL, запись 32 строк раздельно и пакетом, вычисления, JSON, рост журнала, параллельные SQL-вызовы 1/4/8, внешний HTTP и границы SQL-запросов. Итоговый прогон выполнен 17 октября 2026 на постоянном ext4 обоих VPS с одинаковыми Node.js и SQLite. RAM-результаты первоначального стенда в итоговую SQL-таблицу не входят.

В выбранных операциях с базой VPS быстрее. CPU дал близкие результаты, выбранный JSON-тест быстрее прошёл в Telegram. Пакетная запись 32 строк в Telegram заняла 16 мс вместо 533 мс у отдельных запросов. Это сравнение частей приложения; полная задержка клиента Telegram, холодный старт и предел числа пользователей не измерены.

## Запуск

Для локальной копии нужен Node.js 22.13+:

```sh
node --test tests/garden.test.mjs
node tools/preview.mjs
```

Демо: http://127.0.0.1:8765/?demo=1. Оно использует localStorage и не трогает облачный сад. Для настоящего развёртывания получите доступ Serverless у своего бота через @BotFather, установите зависимости, выполните npx tgcloud login, push и отдельно migrate. Адрес MINI_APP_URL замените на адрес своей копии. Подробные команды находятся в [английском README](README.md).

Опубликованы код, синтетические данные benchmark и агрегаты. Токенов, SSH-ключей, адресов VPS, журналов ручных пользователей и реальных Telegram ID участников в репозитории нет. Скриншоты предоставлены автором. Иллюстрации интерфейса явно отмечены как иллюстрации.
