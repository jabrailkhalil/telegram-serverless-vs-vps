# Сравнение Telegram Serverless и двух VPS

Фактический прогон: 10 октября 2026. Числа и ограничения: [report.md](report.md). Машинные данные находятся в `results/`; `metrics.csv` содержит основные показатели, `summary.json` — агрегаты и проверку корректности.

## Метод

Во всех средах используется код `tgcloud/lib/model.js`. Сборщик заменяет только имена таблиц, чтобы изолировать тест от настоящего сада. Начальная база содержит 1000 завершённых поливов. Для каждой операции выполняются 5 прогревочных и 50 измеряемых вызовов. Порядок: чтение, новый полив, повтор уже принятого события. Для записи используются разные синтетические участники; повтор всегда обращается к последнему принятому событию.

После пяти прогревочных и пятидесяти измеряемых поливов ожидаются 1055 записей. Повторы оставляют это число неизменным. Затем выполняются по три раунда четырёх одновременно отправленных вызовов одного и разных участников. На VPS используются четыре worker threads с независимыми соединениями SQLite; в Telegram — четыре независимых управляющих вызова. В каждом раунде ожидается соответственно одна или четыре принятых записи.

Таймер обрамляет вызов общей функции модели, включая SQL и формирование состояния, но исключает внешний транспорт и итоговую сериализацию ответа. В Telegram доступен `Date.now` с шагом 1 мс; на VPS используется `performance.now`. Первые пять операций не включены в распределение. Холодный старт изолята не измеряется.

VPS выполняют один и тот же Node.js 22.23.3 с SQLite 3.51.3, WAL и synchronous FULL. На Германии штатный Node.js 20.20.2 не менялся: для теста скопирован переносимый бинарный файл из уже установленного runtime Финляндии. Он исполнялся только в случайной временной папке и удалён после завершения. SHA-256 бинарного файла: `fde6a4bf8d0562f7751d1a2d6cb9b417c4cfe107bbcb0aa3e9a24e125e348f48`.

Схема Telegram для теста создаётся явным SQL в отдельных таблицах с уникальным префиксом. Они удаляются после прогона. Ранний диагностический вызов выяснил, что платформа запрещает `sqlite_version()` и PRAGMA; оставшиеся от него тестовые таблицы тоже удалены, результат проверки — `results/cleanup.json`. Боевые таблицы сада не использовались для измеряемых записей. На обоих VPS удалены тестовая SQLite и временная папка программы.

## Повторение

Нужны Node.js 22.13+ локально, установленный `@tgcloud/cli` 0.2.0 и SSH-доступ к своим VPS. Локальный сборщик использует внутренний модуль этой версии официального CLI. Это не обещание стабильности внутреннего API в следующих версиях.

Подготовить SSH-конфигурацию вне публикуемого проекта с псевдонимами `fi` и `de`, правильными портами, пользователями, путями к ключам и проверенными known_hosts. Задать путь в `BENCH_SSH_CONFIG`. Скрипт не получает пароли и не копирует SSH-ключи на серверы.

Из корня проекта:

```powershell
$env:BENCH_SSH_CONFIG = 'C:/path/to/private-ssh-config'
node benchmark/collect.mjs vps fi
node benchmark/collect.mjs vps de
```

Для VPS нужен Node.js с `node:sqlite`. При необходимости `BENCH_NODE_REMOTE` задаёт путь к уже установленному бинарному файлу на VPS, а `BENCH_NODE_LOCAL` — к локальному переносимому Linux-бинарному файлу для загрузки только во временную папку теста. Не указывать Windows node.exe для Linux-сервера.

Для облака ввести CLI access token локально в переменную `TGCLOUD_TOKEN`; значение токена не включать в команды, историю или публикации. При установке CLI в нестандартное место задать `TGCLOUD_CLI_MODULE` — путь к `@tgcloud/cli/src/api/endpoints.js`.

```powershell
node benchmark/collect.mjs cloud
```

Для сетевого прогона создать отдельный JSON с целями и задать `BENCH_NETWORK_CONFIG`. Пример структуры:

```json
{
  "telegram": {"host":"appYOUR_ID.tgcloud.ai","servername":"appYOUR_ID.tgcloud.ai"},
  "fi": {"host":"YOUR_VPS_IP","servername":"YOUR_CERTIFICATE_DOMAIN"},
  "de": {"host":"YOUR_OTHER_VPS_IP","servername":"YOUR_CERTIFICATE_DOMAIN"}
}
```

```powershell
node benchmark/collect.mjs network
node benchmark/summarize.mjs
```

TLS-сертификаты проверяются; проверки не отключаются. Выполняется 20 свежих соединений на среду с чередованием целей. TLS-сессии не переиспользуются. Это время до завершения TLS, без HTTP-запроса и кода приложения. Описание `networkContext` в сборщике относится к проведённому прогону; при повторении заменить его на фактические условия своей сети.

Сборщик сохраняет исходные значения. Квантили — nearest rank: элемент `ceil(p × n)` упорядоченного ряда. Скрипт `summarize.mjs` также проверяет размер выборок, принятые поливы, дедупликацию, конкурентные результаты и очистку облачных таблиц. Файл `cleanup.json` относится к выполненному прогону: при повторении нужна новая независимая проверка оставшихся тестовых таблиц.
